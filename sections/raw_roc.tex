\subsection{Data}
For this, we'll use part of a Kaggle data set that was the subject of a \ix{machine learning} competition and is often used for practicing ML models. The goal is \ix{classification}; specifically, to predict which passengers would survive the Titanic\ixh{titanic}{} shipwreck.

We load in the data below and perform any necessary steps -- converting variables to factors as needed, loading the appropriate packages, etc.:
\begin{rcode}
library(tidyverse)        (*@\ixch{library()}\ixch{tidyverse}@*)
library(tidymodels)       (*@\ixch{tidymodels}@*)
library(discrim)          (*@\ixch{discrim}@*)
library(poissonreg)       (*@\ixch{poissonreg}@*)
library(corrr)            (*@\ixch{corrr}@*)
library(ggthemes)         (*@\ixch{ggthemes}@*)
tidymodels_prefer()       (*@\ixch{tidymodels\_prefer()}@*)

set.seed(3000) # can be any number (*@\ixh{random seed}\ixch{set.seed()}@*)

titanic <- read_csv(file = "homework-3/data/titanic.csv") %>% (*@\ixh{titanic}\ixch{read\_csv()}\ixch{\%>\%}@*)
  mutate(survived = factor(survived,          (*@\ixch{mutate()}\ixch{factor()}@*)
                           levels = c("Yes", "No")),   (*@\ixch{levels}@*)
         pclass = factor(pclass),
         coin_flip = c(rep(0, 445), rep(1, 446)))

titanic_split <- titanic %>%
  initial_split(strata = survived, prop = 0.7)  (*@\ixch{initial\_split()}\ixch{strata}\ixch{prop}@*)
titanic_train <- training(titanic_split)  (*@\ixch{training()}@*)
titanic_test <- testing(titanic_split)    (*@\ixch{testing()}@*)
\end{rcode}
We split the data into \ix{training data}\ixh{training/testing split}{} and testing sets\ixh{testing data}, and choose to include $70\%$ of the data in training and $30\%$ in testing. \ixh{stratified sampling}Stratified sampling is important here because the outcome is imbalanced\ixh{class imbalance}; there is a larger number of passengers that didn't survive than passengers that did.

Now we'll create recipes\ixh{recipe()}, and here we are going to specify two recipes -- one that will do pretty well predicting the outcome, and one that won't.

The recipe we'll fit in Homework 3 will do a fairly good job, so we'll use that for what we'll call Recipe A:

\underline{Recipe A:}
\begin{rcode}
titanic_recipe_a <- recipe(survived ~ pclass + sex + age +   (*@\ixch{recipe()}@*)
                           sib_sp + parch + fare, titanic_train) %>%
  step_impute_linear(age, impute_with = imp_vars(sib_sp)) %>%  (*@\ixch{step\_impute\_linear()}\ixch{imp\_vars()}\ixch{impute\_with}\ixh{linear imputation}@*)
  # choice of predictors to impute with is up to you
  step_dummy(all_nominal_predictors()) %>%    (*@\ixch{step\_dummy()}\ixch{all\_nominal\_predictors()}\ixh{dummy variable}@*)
  step_interact(~ starts_with("sex"):age + age:fare)  (*@\ixch{step\_interact()}\ixch{starts\_with()}\ixh{interaction term}@*)
\end{rcode}
For Recipe B, we will attempt to predict passenger survival with only \rc{sib\_sp}, the number of siblings or spouses on board. The goal of this demonstration is to compare an intentionally bad model (Recipe B) to one that is relatively good (Recipe A).

\underline{Recipe B:}
\begin{rcode}
titanic_recipe_b <- recipe(survived ~ sib_sp, titanic_train)  (*@\ixch{recipe()}@*)
\end{rcode}
Note that this recipe is much shorter; there's no age to impute\ixh{imputation}, no categorical predictors\ixh{categorical predictor}, and no interactions\ixh{interaction term}{} (because there's only one \ix{predictor} variable included).

We'll fit two \ix{logistic regression}s, using each of these recipes, and call them Model A and Model B, respectively.

\underline{Model A:}
\begin{rcode}
log_reg <- logistic_reg() %>%    (*@\ixch{logistic\_reg()}@*)
  set_engine("glm") %>%          (*@\ixch{set\_engine()}\ixch{glm}@*)
  set_mode("classification")     (*@\ixch{set\_mode()}@*)

log_wkflow_a <- workflow() %>%   (*@\ixch{workflow()}@*)
  add_model(log_reg) %>%         (*@\ixch{add\_model()}@*)
  add_recipe(titanic_recipe_a)   (*@\ixch{add\_recipe()}@*)

log_fit_a <- fit(log_wkflow_a, titanic_train)  (*@\ixch{fit()}@*)
\end{rcode}
\underline{Model B:}
\begin{rcode}
log_wkflow_b <- workflow() %>%   (*@\ixch{workflow()}@*)
  add_model(log_reg) %>%
  add_recipe(titanic_recipe_b)

log_fit_b <- fit(log_wkflow_b, titanic_train)  (*@\ixch{fit()}@*)
\end{rcode}
We can obtain the \ix{accuracy} for each model:
\begin{rcode}
log_acc_a <- predict(log_fit_a, new_data = titanic_train, type = "class") %>%  (*@\ixch{predict()}\ixch{new\_data}\ixch{type = "class"}@*)
  bind_cols(titanic_train %>% select(survived)) %>%  (*@\ixch{bind\_cols()}\ixch{select()}@*)
  accuracy(truth = survived, estimate = .pred_class)  (*@\ixch{accuracy()}\ixch{truth}\ixch{estimate}\ixch{.pred\_class}@*)
log_acc_b <- predict(log_fit_b, new_data = titanic_train, type = "class") %>%
  bind_cols(titanic_train %>% select(survived)) %>%
  accuracy(truth = survived, estimate = .pred_class)

results <- bind_rows(log_acc_a, log_acc_b) %>%   (*@\ixch{bind\_rows()}@*)
  tibble() %>% mutate(model = c("Model A", "Model B")) %>%  (*@\ixch{tibble()}\ixch{mutate()}@*)
  select(model, .estimate)      (*@\ixch{.estimate}@*)
results
\end{rcode}
\begin{routput}
# A tibble: 2 x 2
  model   .estimate
  <chr>       <dbl>
1 Model A     0.807
2 Model B     0.616
\end{routput}
As expected, Model A has higher accuracy\ixh{accuracy}{} than Model B, and has performed better on the training data\ixh{training error}.

We'll fit both of these to the testing data\ixh{testing data}, and then we'll explore their \ix{ROC curve}s.
\begin{rcode}
log_test_a <- fit(log_wkflow_a, titanic_test)       (*@\ixch{fit()}@*)
log_a_results <- augment(log_test_a, new_data = titanic_test)  (*@\ixch{augment()}@*)

log_test_b <- fit(log_wkflow_b, titanic_test)
log_b_results <- augment(log_test_b, new_data = titanic_test)
\end{rcode}

The \emph{x}-axis, 1 - specificity\ixh{specificity}, is another name for the \textbf{false positive} rate\ixh{FPR}\ixh{false positive}, which is defined as $\frac{FP}{FP+TN}$. \subsection{Model B: ROC Curve:}
\ixh{ROC curve}%
For models that do not predict the outcome as well, it basically doesn't matter where you set the threshold\ixh{threshold}{} value -- that model will NEVER achieve a true positive rate\ixh{TPR}{} of 1 and a false positive rate\ixh{FPR}{} of 0 (which a ``perfect'' classifier can do). Let's take a look at the \ix{ROC curve} of our intentionally bad model:
\begin{rcode}
log_b_results %>%
  roc_curve(survived, .pred_Yes) %>%   (*@\ixch{roc\_curve()}@*)
  autoplot()                           (*@\ixch{autoplot()}@*)
\end{rcode}
\fig{Model B ROC curve (axes as before: x ``1 - specificity'', y ``sensitivity'', dotted diagonal). Only a few corner points, so it is piecewise-linear: a straight segment from (0,0) to $\approx$(0.715, 0.689) lying just \emph{below} the diagonal, then up to $\approx$(0.909, 0.951) crossing slightly above it, a short jump to $\approx$(0.921, 1.00), then flat to (1,1). Essentially the diagonal = no better than random guessing (AUC 0.496).}

It's hard to get much worse than that! Predicting survival solely on the basis of number of siblings or spouses on board is just about as bad as predicting survival based on the result of a coin flip. Let's look at the \ix{confusion matrix}.
\begin{rcode}
log_b_results %>%
  conf_mat(truth = survived, estimate = .pred_class) %>%  (*@\ixch{conf\_mat()}\ixch{.pred\_class}@*)

\end{rcode}
\fig{Model B confusion-matrix heatmap (default threshold 0.5): Pred Yes row = 0 (Truth Yes) and 0 (Truth No); Pred No row = 103 (Truth Yes) and 165 (Truth No). Every passenger is predicted No.}

As we may have suspected -- this model is simply never predicting \rc{Yes}.

It's doing this because there are more \rc{No} values in the data set\ixh{class imbalance}, and therefore predicting No for every observation actually results in what appears to be a relatively high \ix{accuracy} value; the accuracy of this model was about 0.61. But as you'll see, the area under its ROC curve\ixh{AUC}{} is considerably lower. Area under the ROC curve is a metric for how well the model can successfully discriminate between classes, and this model is doing a pretty terrible job of that. In fact, the area under the ROC curve\ixh{AUC}{} for this model is only about 0.50 -- a coin flip:
\begin{rcode}

\subsection{Conclusions}
\ixh{ROC curve}\ixh{model evaluation}%
So what do you take away from here? First, each of these curves is unique to the model's predicted probabilities. That's why the function \ixc{roc\_curve()} will throw an error if you try to give it predicted class values rather than probabilities; it needs the actual probability values in order to calculate \ix{sensitivity} and \ix{specificity} based on a range of thresholds\ixh{threshold}.

The area under an ROC curve\ixh{AUC}{} is, fundamentally, a measure of a model's ability to \textbf{discriminate between classes}. Model A can discriminate between 0 and 1 fairly well; higher p-values, or basically p-values above 0.50, generally correspond to observations that are positive, and lower p-values generally correspond to negative observations, with a few exceptions. Model B \textbf{cannot} discriminate between 0 and 1. The distribution of p-values is about the same for both 0s and 1s; the predicted p-value actually doesn't provide much information about whether an observation is 0 or 1, because the model doesn't know.
{\color{figgray}\itshape [note: ``p-values'' here means the predicted probabilities $p$ = \rc{.pred\_Yes}, not hypothesis-test p-values.]}

ROC curves\ixh{ROC curve}{} have two primary uses in \ix{machine learning}:
\begin{enumerate}
\item Evaluating and comparing model performance\ixh{model comparison}\ixh{model evaluation};
\item Selecting the optimal \ix{threshold} value for a specific model.
\end{enumerate}
To compare model performance\ixh{model comparison}, one usually compares the area under the curve for competing models, preferring the model with an \ix{AUC} value closer to 1. It's also often useful to plot competing ROC curves (you can even do this on the same graph) to get a visual idea of their discriminative abilities. Remember, though, if you have a model whose AUC is \textbf{equal} to 1, that's usually a sign that you've included the outcome, or some linear combination of the outcome, as a predictor\ixh{target leakage}.

Once you've settled on a model, you can also use the \ix{ROC curve} to determine the optimal threshold(s)\ixh{threshold}. This is arguably a less common use, though, because the default threshold(s) typically works well and provides a good balance between \ix{sensitivity} and \ix{specificity}. But if you are working on a project where you want to be extra careful to accurately predict \textbf{every} 0 or, vice versa, every 1, it can be advisable to adjust the threshold in the desired direction.

If you are working with a multiclass outcome\ixh{multiclass classification}, where there are more than two possible values, the ROC curve idea is easily extended! You can generate a curve to represent how well the model distinguishes between \textbf{each} class (we'll see examples of this in the homework and labs).
