\subsection{Introduction}
\ixh{classification}%
This lab will be our first experience with \ix{classification} models. These models differ from the \ix{regression} model we saw in the last chapter by the fact that the response variable is a qualitative variable instead of a continuous variable. This chapter will use `\ixc{parsnip}' for model fitting and `\ixc{recipes} and \ixc{workflows}' to perform the transformations.

\subsubsection{Data}
We'll start out by working with the \rc{Smarket}\ixch{Smarket}{} data set for this lab, which contains daily percentage returns for the S\&P 500 stock index between 2001 and 2005. It contains 1,250 observations on 8 numeric variables, plus a factor variable called \rc{Direction}\ixh{Direction (Smarket)}{} which has two levels, ``Up'' and ``Down''.

Before we go on to modeling, we'll explore the data a little, at least to look at possible correlations\ixh{correlation}{} between the variables. \rc{Direction} is our \ix{outcome} variable of interest; we'll attempt to predict it using the volume of shares traded (\rc{Volume}) and the five lag variables (which represent the percentage return for the previous days).

The other data set we'll work with for this lab is the \rc{OJ}\ixch{OJ}, or Orange Juice, data set. It contains 1,070 observations, each of which represents a customer's purchase of either Citrus Hill or Minute Maid Orange Juice. \rc{Purchase}\ixh{Purchase (OJ)}{} is our outcome variable, which indicates the brand purchased. We'll attempt to predict it using the prices charged for each brand, the discounts offered, and a metric of customer loyalty.

\subsection{Logistic Regression}
\ixh{logistic regression}%
\subsubsection{Creating a Recipe}
First, just as with our \ix{linear regression} lab last week, we want to create a recipe\ixch{recipe()}{} to represent the model we'll be fitting -- one for \rc{Direction} and one for \rc{Purchase}. Neither model has categorical predictors\ixh{categorical predictor}, so we won't need to include \rc{step\_dummy}\ixch{step\_dummy()}\ixh{dummy variable}.
\begin{rcode}
smarket_recipe <- recipe(Direction ~ Lag1 + Lag2 + Lag3 + Lag4 +   (*@\ixch{recipe()}@*)
                           Lag5 + Volume, data = smarket_train)

oj_recipe <- recipe(Purchase ~ PriceCH + PriceMM + DiscCH + DiscMM +  (*@\ixch{recipe()}@*)
         LoyalCH + PctDiscMM + PctDiscCH, data = oj_train)
\end{rcode}

\subsubsection{Specifying an Engine}
Then, again like last week, we specify the model type and engine\ixch{engine}:
\begin{rcode}
log_reg <- logistic_reg() %>%      (*@\ixch{logistic\_reg()}@*)
  set_engine("glm") %>%            (*@\ixch{set\_engine()}\ixch{glm}@*)
  set_mode("classification")       (*@\ixch{set\_mode()}\ixch{mode}@*)
\end{rcode}

\subsubsection{Workflow}
We set up a workflow\ixch{workflow()}, one for each recipe, and fit the models to the \ix{training data}:
\begin{rcode}
smarketlog_wkflow <- workflow() %>%   (*@\ixch{workflow()}@*)
  add_model(log_reg) %>%              (*@\ixch{add\_model()}@*)
  add_recipe(smarket_recipe)          (*@\ixch{add\_recipe()}@*)

smarketlog_fit <- fit(smarketlog_wkflow, smarket_train)   (*@\ixch{fit()}@*)

ojlog_wkflow <- workflow() %>%
  add_model(log_reg) %>%
  add_recipe(oj_recipe)

ojlog_fit <- fit(ojlog_wkflow, oj_train)      (*@\ixch{fit()}@*)
\end{rcode}

\subsection{Fitting to Testing Data}
\ixh{testing data}%
Since the QDA\ixh{QDA}{} model performed slightly better for \rc{Smarket}, we'll go ahead and fit it to the \ix{testing data}. Note that what we are doing -- that is, selecting a model based on its \emph{training accuracy}\ixh{training error}{} -- is \textbf{not} ideal practice, as we've discussed in class. The model with the highest training accuracy is \textbf{not} guaranteed to have high testing accuracy\ixh{testing error}\ixh{overfitting}.

In future weeks, we'll cover how to use \ix{cross-validation} to get an estimate of our models' performance on \emph{testing data} and use that estimate for selecting a model instead. We choose based on training accuracy here \textbf{only because} we haven't discussed cross-validation yet. Choosing a model based on training performance is \textbf{\emph{not a good idea in general}}\textbf{.}

Since we've chosen a model, however -- QDA -- we can view its \ix{confusion matrix} using the \textbf{testing} data:
\begin{rcode}
